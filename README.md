# Прогноз низкой оценки клиента для маркетплейса Olist

Проект посвящён прогнозированию низкой оценки клиента после доставки заказа на маркетплейсе Olist.  
Цель — заранее определить заказы с высоким риском оценки **1–2 звезды**, используя только данные, доступные к моменту доставки: характеристики заказа, оплату, продавца, категорию товара и сроки доставки.

Такой риск-скоринг может использоваться клиентским сервисом для приоритизации проблемных заказов и проактивной работы с клиентами.

## Датасет

Источник данных: [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)

Датасет содержит реальные анонимизированные данные бразильского маркетплейса Olist и состоит из **9 связанных CSV-таблиц**:

- `olist_orders_dataset.csv` — заказы и даты доставки;
- `olist_order_items_dataset.csv` — товары, продавцы, стоимость и доставка;
- `olist_order_payments_dataset.csv` — способы и суммы оплаты;
- `olist_order_reviews_dataset.csv` — оценки клиентов;
- `olist_customers_dataset.csv` — информация о клиентах;
- `olist_products_dataset.csv` — характеристики товаров;
- `olist_sellers_dataset.csv` — информация о продавцах;
- `olist_geolocation_dataset.csv` — географические данные;
- `product_category_name_translation.csv` — перевод категорий товаров.

После SQL-объединения и фильтрации доставленных заказов итоговая таблица содержит **95 824 заказа и 36 признаков**.

Текст отзывов не используется: задача решается без NLP.

## Методология

Работа над проектом состоит из нескольких этапов.

### 1. База данных и SQL

Все 9 таблиц загружаются в SQLite.

Для подготовки признаков используются SQL-запросы с:

- `JOIN` между таблицами;
- `GROUP BY`;
- агрегатными функциями `COUNT`, `SUM`, `AVG`, `MAX`;
- CTE (`WITH ... AS`);
- расчётом признаков на уровне одного заказа.

Перед объединением таблицы с товарами и платежами агрегируются до уровня `order_id`, чтобы избежать размножения строк.

После формирования итоговой таблицы проверяется условие:

```text
одна строка = один заказ
```

### 2. Разведочный анализ данных

В EDA исследуются:

- распределение оценок клиентов;
- пропущенные значения;
- доля негативных оценок;
- влияние опоздания доставки;
- различия между категориями товаров;
- характеристики заказов, связанные с негативной оценкой.

### 3. Целевая переменная

Исходная оценка клиента преобразуется в бинарную задачу:

```text
target = 1 → оценка 1–2 звезды
target = 0 → оценка 3–5 звёзд
```

Доля класса `1` составляет около **12,8%**, поэтому задача имеет выраженный дисбаланс классов.

### 4. Машинное обучение

Данные разделяются на:

- train — 70%;
- validation — 15%;
- test — 15%.

Сравниваются две модели:

- **Logistic Regression** — базовая интерпретируемая модель;
- **CatBoost Classifier** — градиентный бустинг с поддержкой категориальных признаков.

Для Logistic Regression используются:

- заполнение числовых пропусков медианой;
- стандартизация;
- One-Hot Encoding категориальных признаков;
- `class_weight='balanced'`.

Для CatBoost категориальные признаки передаются напрямую, а баланс классов учитывается через `auto_class_weights='Balanced'`.

Порог классификации выбирается на validation-выборке по максимальному F1, а итоговые метрики рассчитываются на test-выборке.

Основная метрика проекта — **PR-AUC**, поскольку она лучше подходит для оценки качества модели при дисбалансе классов.

Дополнительно используются:

- ROC-AUC;
- Precision;
- Recall;
- F1-score;
- Confusion Matrix;
- Lift@10%.

## Результаты

Основные результаты на test-выборке:

| Модель | ROC-AUC | PR-AUC | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|
| CatBoost | 0.759 | 0.473 | 0.481 | 0.468 | 0.474 |
| Logistic Regression | 0.751 | 0.428 | 0.441 | 0.475 | 0.457 |

Ключевые находки:

- низкие оценки **1–2 звезды составляют около 12,8%** всех анализируемых заказов;
- среди заказов с опозданием доля низких оценок составляет около **54,1%**, а среди доставленных вовремя или раньше — около **9,2%**;
- риск низкой оценки при опоздании примерно в **5,86 раза выше**;
- лучшую PR-AUC среди двух моделей показал **CatBoost — 0,473** при baseline около **0,128**;
- в **Top-10% заказов с максимальным прогнозируемым риском** доля реальных низких оценок достигает **53,8%**, что соответствует **Lift@10% ≈ 4,20x**.

Наиболее важными признаками CatBoost оказались:

1. задержка доставки относительно обещанной даты;
2. общее время доставки;
3. количество товаров в заказе;
4. объём товара;
5. категория товара;
6. стоимость доставки.

## Бизнес-применение

Модель предлагается использовать не как автоматическое решение о компенсации клиенту, а как инструмент **приоритизации заказов по риску**.

Например, клиентский сервис может:

- проактивно связываться с клиентами после проблемной доставки;
- быстрее обрабатывать обращения заказов с высоким риском;
- предлагать промокод или компенсацию в отдельных случаях;
- отслеживать продавцов, категории товаров и логистические сценарии с повышенным риском негативной оценки.

## Ограничения

- Данные Olist относятся к ограниченному историческому периоду и могут не отражать текущую ситуацию на рынке.
- В датасете нет полной информации о качестве товара и фактическом взаимодействии клиента со службой поддержки.
- Текст отзывов намеренно не используется.
- Модель показывает вероятность негативной оценки, а не гарантирует конкретное поведение клиента.
- Результаты требуют дополнительной проверки перед использованием в реальном бизнес-процессе.
- Feature importance CatBoost показывает вклад признаков в модель, но сама по себе не доказывает причинно-следственную связь.
